AI网关 全局隐私绑定桥接契约

范围
新增 backend/privacy_gateway_bridge.py 与 cloud/lib/privacy-gateway-bridge.ts；冻结privacy.py/privacy-api.ts及公共入口尚未修改。视频源、构建、服务与测试均未触碰。
本桥只决定“全局隐私披露是否已按当前实际处理方确认”。它不建立任何provider receipt，不发请求、不授权资料分类、不改会员或正式额度。

全局绑定
Python global_binding(cfg, legacy, gateway, legacy_binding=None)
Cloud globalBinding(cfg, legacy, gateway, actualLegacy?)（异步）
1. 调用旧actual_binding/actualBinding；若有效，完整原样返回原details和digest。集成点传入原函数，完全保留旧序列化与旧确认行为；gateway配置是否完整不影响有效legacy优先级。
2. 旧绑定无效时，要求gateway.environment=local-test，四场景chat/chart/course/card的routes完整，取所有非空primary及fallback引用ID去重排序。
3. 所有引用ID在registry唯一存在；逐个与privacy.recipients同ID匹配：合法HTTPS完整endpoint须raw完全相等，模型列入该接收方models，实际处理地区集合相同，provider.privacyPolicyVersion等于全局policyVersion。无引用、缺披露、重复ID、未知引用、字段/协议不符均fail closed。
4. details={mode:'gateway-registry',schemaVersion:1,policyVersion,providers:[按providerId排序的必要绑定字段]}。确定性canonical JSON按Unicode码点排序key/地区，UTF-8 SHA-256；不含secretRef、密钥、提示词、额度、内部超时或网关revision。不引用的provider不进入聚合摘要。
5. 聚合details没有单独providerId；旧客户端不能将它当作legacy出站配置。registry UI需按mode分支展示各provider，并逐个走实际网关receipt确认。

完整本人响应hook
Python bridge_privacy_response(base, legacy, gateway, legacy_binding=None, account_id=None)
Cloud bridgePrivacyResponse(base, legacy, gateway, actualLegacy?, accountId?)（异步）
base为冻结Privacy.response()/GET preferences完整本人结果。helper纯overlay重算disclosure.configured/providerBinding/activeAI、policyAcknowledged、consentEpoch及当前已授权资料类别；不写数据库。最后账号参数可强制匹配当前请求owner。
供网关独立内存测试注入：Python privacy_response=lambda: bridge_privacy_response(Privacy(...).response(), store.setting('ai'), store.setting('ai_gateway'), actual_binding, owner)；Cloud a.aiGatewayPrivacyResponse()对应异步调用。
hook不能让冻结的偏好PATCH凭空接受聚合确认；实际应用须执行下述接入脚本，使全局偏好提交和响应采用同一绑定。

逐供应商授权仍是独立条件
全局偏好只保存global providerBinding。网关个人receipt保存每provider自己的binding、policyVersion、globalRevision、独立nonce和categories；两种binding不能混用。
global确认不创建个人receipt；A供应商receipt不授权B或fallback，A账号不授权B账号。全局撤回/删除使revision变化，旧receipt无效；重新确认全局也不自动恢复旧receipt。
